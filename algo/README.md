## 2. Как запускать в Zed («кнопка Play»)

Zed не показывает для C такую же кликабельную стрелку в гуттере, как Visual Studio,
поэтому роль кнопки выполняет горячая клавиша:

| Клавиша | Действие |
|---|---|
| **F5** | Compile & Run — скомпилировать открытый `.c` и запустить в терминале Zed |
| **Ctrl+F5** | То же самое (дубль для привычки из Visual Studio) |
| **Alt+F6** | Только компиляция, без запуска |
| **Alt+T** | Повторить последнюю задачу (`task::Rerun`, встроенное в Zed) |
| Ctrl+Shift+P → `task: spawn` | Выбрать задачу из списка вручную |

Скрипт `.zed/run-c.ps1` сам:
- находит `gcc` в PATH (или по известным путям MinGW),
- компилирует с `-std=c11 -O2 -Wall -Wextra -g`,
- останавливается, если сборка не удалась,
- запускает `.exe` из папки исходника и показывает код выхода.

Любой `.c`-файл запускается одинаково: открой его, нажми F5. В том числе `qsort_test.c`.

## 3. Среда

**Среда, в которой получены числа в отчётах:**
> macOS arm64, Apple clang 17, C11, оптимизация `-O2`.

Эту строку в отчётах менять не нужно — именно здесь делались все замеры.

**Локальная среда (этот компьютер, запуск из Zed):**
> Windows x86_64, MinGW-w64 GCC 15.1.0, target `x86_64-w64-mingw32`,
> системная библиотека MSVCRT, C11, `-O2`.

### Про `RAND_MAX` и случайные числа

- На macOS `RAND_MAX = 2³¹−1`, поэтому `rand() % 1000000` полностью покрывает диапазон 1…10⁶.
- На локальном Windows `RAND_MAX = 32767` (2¹⁵−1). Это ограничение **системной CRT**,
  а не компилятора: clang под Windows с теми же заголовками даст те же 15 бит.
- На результаты отчёта это не влияет: замеры сделаны на macOS.
- Если понадобится 31 бит на Windows, не меняя компилятор, можно собрать значение из
  двух вызовов `rand()` (по-прежнему «через srand/rand», как требует задание):

```c
int r = (int)(((unsigned)rand() << 15) | (unsigned)rand());
int x = min_val + r % (max_val - min_val + 1);
```

В код лабораторных это **не вносилось**, чтобы текст программы совпадал с отчётом.

## 4. Лабораторная №1 — поиск

### Что требовалось

1. Функции формирования массивов: случайного, возрастающего, убывающего.
   Память выделяется **вне** функций, функции получают указатель, размер и диапазон.
2. Три алгоритма поиска в отдельных функциях, все вызываются из одного `main`:
   - `BLS` — обычный линейный;
   - `SLS` — линейный с барьером;
   - `BS` — бинарный.
3. Замеры времени и счётчиков для размеров 50000…500000 и трёх позиций ключа:
   начало, середина, отсутствие.

### Счётчики

- `counter1` (`C1`) — сравнения ключа с элементом массива;
- `counter2` (`C2`) — проверки границ / обращения к элементам.

`BLS` и `SLS` получают один и тот же случайный массив, `BS` — возрастающий (иначе бинарный поиск некорректен).

### Ключевые результаты

- `SLS` быстрее `BLS` за счёт барьера в `a[n−1]`: проверка `i < n` исчезает из цикла, поэтому `C2 = 0`.
- `BS` — O(log n): при росте n в 10 раз число сравнений выросло примерно с 30 до 36.
- Ключ в начале — лучший случай для линейных (O(1)), но для `BS` это всё равно log n.
- Ключ отсутствует — худший случай: BLS/SLS проходят весь массив, BS сужает интервал.
- `BS` применим только к отсортированным данным.

В отчёте результаты оформлены таблицами и графиками (скриншоты Excel).

## 5. Лабораторная №2 — сортировки

### Что требовалось

Исследовать 5 методов, причём быстрая сортировка в двух вариантах — итого 6:

| № | Метод | Функция |
|---|---|---|
| 0 | Выбором | `selectionSort` |
| 1 | Вставками | `insertionSort` |
| 2 | Слиянием | `mergeSort` |
| 3 | Быстрая, последний опорный (Ломуто) | `quickLastSort` |
| 4 | Быстрая, схема Хоара | `quickHoareSort` |
| 5 | Шелла | `shellSort` |

Для каждого: три типа входа (случайный, возрастающий, убывающий), одинаковые исходные
данные для всех методов (`srand(42)`), размеры 15, 500, 1000, 10000, 50000, 100000.

- **Этап 1** (n = 15): все промежуточные состояния массива, сравнения `C` и пересылки `M`.
- **Этап 2** (n = 500…100000): время `t`, сравнения `C`, пересылки `M`.

### Определения счётчиков

- `C` — сравнения значений элементов;
- `M` — присваивания значений элементов: ключ, опорный, буфер. Обмен двух разных элементов = 3 пересылки, обмен с собой пропускается.
- Время измеряется `clock()` **только** вокруг сортировки: без генерации, копирования, выделения памяти, печати и проверки.

### Сложность

| Метод | Лучший / средний / худший | Память |
|---|---|---|
| Выбором | Θ(n²) / Θ(n²) / Θ(n²) | O(1) |
| Вставками | Θ(n) / Θ(n²) / Θ(n²) | O(1) |
| Слиянием | Θ(n log n) во всех случаях | O(n) |
| Быстрая, последний | Θ(n log n) / Θ(n log n) / Θ(n²) | O(log n) |
| Быстрая, Хоар | Θ(n log n) / Θ(n log n) / Θ(n²) | O(n) в худшем случае |
| Шелла (шаг/2) | зависит от входа / O(n²) | O(1) |

### Главные выводы

- Выбором: ровно n(n−1)/2 сравнений независимо от порядка; при n=100000 это ~5·10⁹ сравнений и ~7 с.
- Вставками: идеальны для маленьких и почти отсортированных массивов; на возрастающем n=100000 — 0.000079 с, на убывающем — уже 1.82 с.
- Слиянием: гарантированные Θ(n log n) и устойчивость, но O(n) памяти; лучшее время на случайном n=100000 — 0.005137 с.
- Последний опорный: на упорядоченных входах вырождается в O(n²) (2.49 с на возрастающем n=100000).
- Хоар со средним опорным на тех же входах делит массив почти пополам: 0.000966 с на убывающем n=100000.
- Шелл — компактный O(1) вариант для средних массивов; при делении шага пополам худшая оценка остаётся O(n²).
- Упорядоченный массив — не «лучший случай» для всех алгоритмов.

## 7. Шпаргалка для защиты

**Почему у SLS `C2 = 0`?** Ключ пишется в `a[n−1]`, цикл всегда находит барьер, проверка границ в условии не нужна.

**Почему BS требует отсортированный массив?** Он отбрасывает половину по результату сравнения; это верно только при монотонности.

**Зачем `left + (right-left)/2`?** Защита от переполнения `int`.

**Чем Ломуто отличается от Хоара?** Опорный последний vs средний, один указатель vs два встречных; на упорядоченных данных Ломуто даёт разбиение 0 и n−1, Хоар — почти равные половины.

**Зачем рекурсия только на меньшей части?** Чтобы глубина стека была O(log n) при любом разбиении; большая часть обрабатывается в цикле.

**Почему у слияния `M` не зависит от порядка?** Схема рекурсии и число записей в буфер и обратно одинаковы для любого входа.

**Почему у выборки `M = 3⌊n/2⌋`?** Обмен разных элементов — 3 пересылки, обмен с собой пропускается.

**Почему у вставок на возрастающем `M = 2(n−1)`?** Одно сохранение ключа и одна запись ключа на проход.

**Устойчивость?** Устойчивы вставки и слияние; выбор, Шелл и обе быстрые — нет.

**Время BS почти нулевое?** У `clock()` грубое разрешение, а операций единицы; для честного замера нужно повторять поиск много раз.
